# راهنمای کامل نصب و استفاده — ماژول مدیریت چک (Level 1)

این ماژول کاملاً **مستقل** است و هیچ‌کدام از فایل‌های فعلی ERP را تغییر نمی‌دهد
(به‌جز افزودن یک ستون اختیاری `check_id` به `bank_transactions` که آن هم فقط در صورت
نبود ستون انجام می‌شود). حذف ماژول هم ساده است: فایل `cheques.php` را پاک کنید.

---

## الف) نصب (۳ دقیقه)

1. فایل **`deploy/deploy_cheques.php`** را باز کنید و کل محتوایش را کپی کنید.
2. در cPanel → File Manager:
   - فایل `/home/adapharm/public_html/checkmodel.php` را بسازید/باز کنید و محتوا را داخلش پیست و ذخیره کنید.
3. در مرورگر (یک‌بار، با ۵ ثانیه تأمل):
   ```
   https://adapharmaco.com/checkmodel.php?token=MyStrongPass_2026_xyz
   ```
   - خروجی باید ۷ گام را با ✅ نشان دهد:
     تشخیص محیط ← اتصال DB ← ساخت ۴ جدول ← ثبت v2.7.0 ← نوشتن cheques.php ← پوشه آپلود ← راستی‌آزمایی.
4. بعد از دیدن ✅ها، **فایل `checkmodel.php` را از سرور حذف کنید**.
5. وارد ERP شوید و باز کنید:
   ```
   https://erp.adapharmaco.com/cheques.php
   ```
   (ماژول از سشن لاگین ERP استفاده می‌کند؛ اگر لاگین نباشید صفحه «ابتدا وارد شوید» می‌دهد.)

> اگر گام ۵ نوشت «ریشه ERP پیدا نشد»، همان فایل را به‌جای public_html در
> `/home/adapharm/erp/checkmodel.php` کپی و آدرس
> `https://erp.adapharmaco.com/checkmodel.php?token=...` را اجرا کنید.

### افزودن لینک به منوی کناری (اختیاری، دستی)
در `app/views/layouts/main.php` کنار سایر لینک‌ها این خط را اضافه کنید:
```php
<li class="nav-item"><a class="nav-link" href="/cheques.php">🏦 مدیریت چک‌ها</a></li>
```
(تا بعد از بازآرایی MVC، لینک مستقیم به فایل ریشه است.)

## ب) گردش کار روزانه

### ثبت چک دریافتی (از مشتری)
`＋ ثبت چک جدید` ← تب **«💵 چک دریافتی»**:
مبلغ، شماره چک، **شناسه صیاد** (یکتایی چک می‌شود)، بانک/شعبه، انتخاب مشتری،
تاریخ سررسید، اسکن پشت/رو، و اتصال به شماره فاکتور در توضیحات/سند.
وضعیت اولیه: **در دست**.

### ثبت چک صادره (به تأمین‌کننده)
تب **«💸 چک صادره»**:
- اول (یک‌بار) دکمه پایین صفحه «ثبت دفترچه چک جدید» را بزنید و محدوده شماره برگه‌ها را وارد کنید.
- بعداً با انتخاب دفترچه، **شماره چک بعدی خودکار** پیشنهاد می‌شود.
- ذی‌نفع (تأمین‌کننده)، مبلغ، سررسید را وارد کنید. وضعیت: **صادر شد**.

### چک تضمینی (وثیقه)
تب‌های **«🤝 تضمینی دریافتی/صادره»** — بابت وثیقه و تاریخ استرداد مورد انتظار را وارد کنید.
وضعیت این چک‌ها **در وثیقه** است و با عملیات «مسترد شدن» یا «ضبط/اجرا» تعیین تکلیف می‌شود.

### روی هر چک (صفحه جزئیات) عملیات مجاز نشان داده می‌شود:
| وضعیت | عملیات |
|---|---|
| در دست | سپرده به بانک · **خرج/انتقال چک** · ابطال · جایگزینی |
| سپرده‌شده | **ثبت وصول** · **ثبت برگشت** |
| برگشت (دریافتی) | سپرده مجدد · جایگزینی · ابطال |
| صادر شد | **ثبت پاس‌شدن** · **ثبت برگشت** · ابطال · تمدید/جایگزینی |
| در وثیقه (تضمینی) | مسترد شدن · ضبط/اجرا |

- عملیات‌های ⚠️‌دار (وصول، پاس‌شدن، برگشت، انتقال، ابطال، ضبط) **حساس** هستند:
  ثبت می‌شوند ولی وضعیت چک فقط بعد از **تأیید کاربر دوم** (که ثبت‌کننده نباشد) عوض می‌شود.
- تأییدها در منوی **«تأییدها»** بالای صفحه انجام می‌شود (Maker–Checker).

### انتقال/خرج چک (Endorsement)
روی چک دریافتی عملیات **«خرج/انتقال چک»** را بزنید و نام دریافت‌کننده (تأمین‌کننده)
و بابت (سفارش خرید/معامله) را وارد کنید. سابقه انتقال‌ها در پایین صفحه چک بایگانی می‌شود.

## ج) گزارش‌ها و هشدارها
- **داشبورد:** چک دریافتی در جریان، سررسید ۷ روز آینده (یادآور سپرده‌گذاری)،
  چک صادره ۷ روز آینده، برگشتی‌ها، تضمینی‌های در وثیقه، صف تأیید.
- 🚨 **هشدار کسری موجودی:** برای هر حساب، جمع چک‌های صادره ۳۰ روز آینده با
  مانده ثبت‌شده حساب مقایسه و کسری قرمز می‌شود (اگر مانده حساب در جدول
  `bank_accounts` ستون داشته باشد؛ وگرنه «دستی کنترل شود» می‌گوید).
- **گزارش‌ها:** Aging چک دریافتی (جاری/۱-۳۰/۳۱-۶۰/...)، برنامه روزانه چک‌های صادره، فهرست تضمینی‌ها.

## د) امنیت و کنترل‌ها (چرا «سختگیرانه» است)
1. **ماشین وضعیت قفل‌شده:** وضعیت چک فقط با عملیات مجازِ وضعیت فعلی عوض می‌شود؛
   بعد از وصول/پاس/ابطال/انتقال/استرداد، چک 🔒 قفل می‌شود.
2. **لجر رویدادها append-only:** هیچ رویدادی ویرایش/حذف نمی‌شود؛ هر رویداد
   **hash رویداد قبلی** را دارد (زنجیره) — هر دستکاری قابل کشف است.
3. **Maker–Checker:** عملیات مالی حساس نیازمند تأیید کاربر دوم است.
4. **یکتایی صیاد:** ثبت شناسه تکراری جلوگیری می‌شود.
5. **CSRF token** روی همه فرم‌ها و سشن‌محور بودن دسترسی.

## و) بازگشت (Rollback)
- ماژول: فایل `/home/adapharm/erp/cheques.php` را حذف کنید (بکاپ خودکار با پسوند `.bak-تاریخ` ساخته شده).
- جداول دست‌نخورده می‌مانند؛ برای حذف کامل:
```sql
DROP TABLE IF EXISTS check_endorsements, check_events, checkbooks, checks;
DELETE FROM schema_migrations WHERE version='v2.7.0';
```

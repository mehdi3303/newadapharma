# ایده‌های هوشمندسازی: استعلام چک + ریسک‌اسکور + چرخه صیاد
(پیش‌نویس ایده — در انتظار تأیید کاربر؛ هنوز پیاده‌سازی نشده)

## واقعیت دسترسی
- استعلام رسمی صیاد (وضعیت چک + سابقه برگشتی صادرکننده / محرومیت دسته‌چک) از مسیرهای رسمی است:
  درگاه API بانک/شاپرک (نیازمند قرارداد و کلید کسب‌وکاری)، یا دستی via پیامک/اپ بانک/آپ.
- روی CloudLinux اشتراکی بدون کلید، استعلام زنده مستقیم نداریم → راهکار دو لایه:
  - **لایه A (همین حالا):** نیمه‌خودکار + ریسک‌اسکور داخلی + پارس هوشمند پاسخ.
  - **لایه B (با دسترسی API):** کانکتور زنده بانکی به‌صورت پلاگین.

---

## ۱) ربات استعلام نیمه‌خودکار صیاد (لایه A — بدون نیاز به API)
روی هر چک دریافتی دکمه «استعلام صیاد»:
1. اعتبارسنجی فرمت شناسه ۱۶ رقمی صیاد.
2. انتخاب بانک → نمایش **شماره پیامک استعلام همان بانک + متن آماده** (دکمه «کپی متن» و «باز کردن پیامک‌رسان»).
3. کادر «پاسخ بانک را اینجا بچسبانید» → سیستم **متن پاسخ را هوشمند می‌خواند** و این‌ها را استخراج می‌کند:
   وضعیت چک (ثبت/تأیید/رد/وصول/برگشت)، تعداد و مبلغ چک‌های برگشتی صادرکننده، محرومیت دسته‌چک.
4. نتیجه در جدول `check_inquiries` (تاریخچه استعلام هر چک و هر طرف) ذخیره و روی تایم‌لاین چک می‌آید.

## ۲) امتیاز اعتبار چک (Cheque Reputation Score) — داخلی و هوشمند
به‌ازای هر مشتری/تأمین‌کننده از داده‌های خود سیستم:
- نرخ برگشت چک، میانگین تأخیر وصول، دفعات تمدید/جایگزینی، چک‌های سررسیدگذشته باز.
- ترکیب با `tp_customer_payment_profile` (پیش‌بینی پرداخت TradePilot).
- خروجی: امتیاز ۰–۱۰۰ + رنگ ریسک هنگام ثبت چک جدید (پیش از قبول) + توصیه:
  **قبول / اخذ چک ضامن یا پیش‌پرداخت / رد**.
- هشدار قرمز اگر صادرکننده در استعلام، محروم از دسته‌چک باشد.

## ۳) چرخه عملیاتی صیاد (یادآور + وضعیت)
- دریافتی: یادآور «تا ۴۸ ساعت پس از دریافت باید در صیاد تأیید شود» (وگرنه قابل وصول/انتقال نیست).
- صادره: یادآور «قبل از تحویل، چک را در صیاد ثبت کن» + فیلد کد پیگیری ثبت.
- وضعیت‌های صیاد (ثبت/تأیید/رد/وصول/برگشت) به‌صورت رویداد در لجر چک.

## ۴) پارس هوشمند پاسخ + تولید سند حقوقی
- تشخیص خودکار مفاد پیامک برگشت/استعلام و ساخت رکورد ساخت‌یافته.
- هنگام برگشت چک: پیش‌نویس خودکار **اخطاریه/اظهارنامه** از طریق سیستم Official Letters با رعایت مهلت‌های قانونی (واخواست/اعتراض، پیگیری اجرایی).

## ۵) تصمیم هوشمند TradePilot
- اسکالیشن خودکار به دپارتمان Finance برای چک پرریسک/برگشتی با پیشنهاد اقدام.
- تغذیه ریسک چک در پیش‌بینی نقدینگی: چک پرریسک با وزن وصول کمتر در cashflow ۹۰ روزه.

## ۶) OCR اسکن چک (منوط به سرویس بینایی)
- خواندن خودکار شماره چک، صیاد، مبلغ، تاریخ از عکس → پر کردن فرم با تأیید انسان.

## ۷) کانکتور زنده بانکی/شاپرک (لایه B — منوط به دسترسی)
- معماری پلاگین: کلید API در جدول settings؛ استعلام واقعی یک‌دکمه‌ای.
- نیاز: مشخص شود کدام بانک حساب شرکتی دارد و آیا دسترسی اینترنت‌بانک شرکتی/API (شاپرک/PGS) گرفته شده.

## جداول پیشنهادی (لایه A)
- `check_inquiries(id, check_id, party_type, party_id, sayyad_id, channel ENUM('sms','app','api'),
   raw_response TEXT, parsed_status, bounced_count, bounced_amount, is_banned TINYINT,
   risk_score TINYINT, risk_level ENUM('low','medium','high'), inquired_by, inquired_at)`
- افزودن به `checks`: `sayyad_status`, `sayyad_registered_at`, `sayyad_confirmed_at`.
- (گزینه) `party_cheque_reputation` به‌صورت VIEW تجمیعی از checks + check_inquiries.

## پیشنهاد ترتیب اجرا
- فاز اول (الان): ۱ + ۲ + ۳ + ۵ (کاملاً داخلی، بدون وابستگی بیرونی).
- فاز دوم: ۴ (اسناد حقوقی) و ۶ (OCR) در صورت دسترسی.
- فاز سوم: ۷ کانکتور زنده در صورت تأمین دسترسی API بانکی.
